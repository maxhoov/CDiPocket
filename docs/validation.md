# 验证记录

当前是 0.1.0 工程验证版，版本号由 0.2.6-dev 重置，位流及其验证结果不变。用户已确认此前版本可正常进入游戏，表明 OS 2.7 的 Ready to Run 启动阻塞已解决，但尚未建立完整兼容性清单。0.2.5-dev 加入加载黑屏后收到持续黑屏反馈；本版补上 CDI/2352 CUE 轨道支持，修正显示就绪条件并增加真实 MCD212 回归，仍需实机复测，见 [修复记录](boot-fix.md)。

构建摘要以 `dist/fit.summary`、`dist/timing.summary`、`dist/validation.json` 为准。最后一轮打包校验确保 FPGA 源码与位流对应，目标为 `5CEBA4F23C8`，全部已报告的 setup / hold / recovery / removal / pulse-width 时序裕量非负。

2026-10-04 的 0.2.6-dev 构建：9881 / 18480 ALM（53%），1942016 / 3153920 块内存位（62%），245 / 308 RAM 块（80%），27 / 66 DSP，2 / 4 PLL。最小 setup 裕量为 2.314 ns，最小 hold 裕量为 0.144 ns；84 项汇总时序裕量均非负。完整布局布线成功，0 个错误、376 个警告；随后更新文件管理固件的 RAM 初始化并重新生成位流，更新及汇编成功，最终时序复核成功。无新增 RAM 或 DSP，原外部 I/O 约束限制仍适用。

2026-10-03 的 0.2.5-dev 构建：9836 / 18480 ALM（53%），1942016 / 3153920 块内存位（62%），245 / 308 RAM 块（80%），27 / 66 DSP（41%），2 / 4 PLL。相对 0.2.4-dev，净增加 10 个 ALM，没有增加 RAM 或 DSP。最小 setup 裕量为 2.395 ns，最小 hold 裕量为 0.224 ns；35 项汇总时序裕量均非负。综合、布局布线和位流生成成功，时序脚本复核成功。报告无组合回路，未约束时钟数为零；原有外部 I/O 约束限制仍适用。

2026-10-03 的 0.2.4-dev 最终构建：9826 / 18480 ALM（53%），1942016 / 3153920 块内存位（62%），245 / 308 RAM 块（80%），27 / 66 DSP（41%），2 / 4 PLL。最小 setup 裕量为 2.024 ns，最小 hold 裕量为 0.127 ns。Quartus 完整编译成功、0 个错误、378 个警告；保留模块、文件管理 CPU 和 APF 框架仍产生综合警告，不能将本构建描述为无警告。暂停时钟使用专用 `CLKCTRL_G5 / GCLK5`；最终报告无组合回路，未约束时钟数为零。

0.2.4-dev 的完整回归已通过 6 个原生光盘单元测试，以及 `tb_adapters`、`tb_memory`、`tb_video`、`tb_servo`、`tb_native_disc`、`tb_framework`、`tb_boot`、`tb_startup`、`tb_pause` 九组 HDL 仿真；启动集成测试另通过 BIOS 失败场景，记录为 `tb_startup_failure`。脚本同时检查退出码、成功标记及 Fatal / Error 日志，防止仿真提前终止后被误认为通过。对应日志在 `build/sim/`，整套运行记录在 `build/logs/test.log`；明确暂停状态寄存器后的专项回归记录在 `build/logs/menu_pause_test.log`，最终通过状态记录在 `dist/validation.json`。

`tb_startup` 按 OS 2.7 日志顺序检查框架 Ready to Run 及 Reset Exit，再服务 Target 文件命令。生产启动和仲裁模块与实际 RV32I 固件、FIFO、SDRAM 控制器相连，校验完整 512 KiB 模拟 BIOS 和 8 KiB 模拟 Slave 的传输、无加载溢出、CPU 复位保护、CUE / 多 BIN 初始化、菜单保存握手及核心复位。SDRAM 写入内容通过引脚上的行、列、数据核对。失败场景要求 BIOS 读取错误后 CPU 仍保持复位。该测试不执行真实 BIOS 指令，也不模拟真实 SD 卡延迟或保存文件写入。

`tb_framework` 通过实际 APF 双线 SPI 而非直接寄存器模拟访问，覆盖冷启动命令、OS 通知、首次数据槽请求参数及 NVRAM 暂停确认、Ready to Run / Running / Idle，以及原生 RAM、NVRAM 和命令区域之间的返回数据流水线。0.2.2-dev 的数据槽测试使用生产许可模块，按日志依次请求 CUE、BIOS、Slave、NVRAM，并检查 BIN 及大小边界；旧许可条件可重现 CUE 槽返回 `0002` 的失败。`tb_boot` 保留完整 1 MiB 清零，验证约 0.5 ms 即可接收资源、100 ms 的启动状态查询、清零期间完整 Slave 加载、无 FIFO 溢出及后台刷新；恢复旧启动条件时可重现十次 Booting 响应。原有 4 KiB 内存仿真继续验证具体读写数据、字节掩码和突发传输。

最终启动仿真在 0.500 ms 打开资源接收，109.562 ms 完成 524288 个字的清零；期间检查了 15961 次刷新，连续刷新间隔不超过 8 μs。物理 SPI 测试还证明原直接区域选择器会丢失跨区域上一笔返回数据，而统一返回缓冲通过全部检查。实机启动证据来自用户对 0.2.3-dev 的反馈，不由这些仿真推断。

光盘单元测试直接编译并调用核心使用的 C 解析与扇区生成代码，覆盖单 / 多 BIN、99 个 BIN / 轨道、带空格 / UTF-8 路径、BOM / CRLF、INDEX / PREGAP、FLAGS、TOC / Q CRC、去扰码、PCM 字节顺序、缺文件 / 截断 / 不支持格式与读取失败。

`tb_native_disc` 使用实际 PicoRV32、实际 `firmware.mif` 与厂商 RAM 仿真模型，模拟 APF 获取文件名、打开 BIN、更新大小表和按偏移读取。BIN 的大小表项特意放在非 ID 对应下标，验证按 ID 查找。独立参考数据核对 13 个 TOC / 间隙 / Mode 2 / 扰码 / 音频 / 多 BIN / lead-out 记录的全部 1284 个字，并检查 EOF、复位恢复与失败读取无部分提交。

菜单回归使用厂商 Cyclone V 时钟使能仿真模型。`tb_pause` 在真实 SDRAM 突发中请求暂停，要求全部四字及完成确认先被消费；暂停期间不增加机器周期、控制器计时或伪造 NVRAM 事件，继续检查刷新间隔不超过 8 μs，I²S 保持静音且恢复原立体声采样。它也检查恢复前排空刷新、重复菜单、复位覆盖和无短时钟脉冲。`tb_framework` 用实际 SPI 发出菜单通知，`tb_native_disc` 验证暂停时完成的读取和中途扇区流，`tb_video` 验证消隐冻结及视频计数恢复。仿真不替代 Pocket 的菜单显示、声音及持续游戏实测。

该仿真的 CUE 解析启动约 22 ms；13 个请求中首次数据扇区包含一次性扰码表初始化，用时 12.504 ms，其余请求约 1.027–3.252 ms。这些数据使用模拟 APF 文件操作，不包含真实 SD 卡延迟，不能证明实机持续 75 扇区 / 秒读取性能。

仿真使用独立的模拟数据，不依赖商业 BIOS 或游戏。SDRAM 模型覆盖本项目采用的几何、CAS=2 与四字读突发；它是协议测试模型，不是完整的厂商器件模型。

APF 模板未给 Bridge / PAD 物理通信和 scaler 的外部器件提供完整板级输入输出延迟。本工程补充了 SDRAM 外部约束；沿用框架的其余外部接口仍需通过 Pocket 实机验证。报告中的这些未约束 I/O 不应被理解为全部板级时序已经验证。

## 实机验收

CDI/2352 新增单元测试及其余六个原生光盘测试全部通过。同一实机 CUE 的生产解析返回码由 2 变为 0；对实际 BIN 的五个采样扇区成功生成记录并验证 Q CRC。检查不修改 SD 卡资源。原生 RV32I / 完整启动专项使用 CDI/2352 合成轨道，日志分别为 `build/sim/tb_native_disc.log`、`build/sim/tb_startup.log` 和 `build/sim/tb_startup_failure.log`。 三项回归均已通过：原生光盘模拟 55.801 ms，完整启动模拟 78.559 ms，失败场景模拟 1.810 ms；均为 0 个错误。启动失败场景仍有框架 / 厂商模型的 11 个端口连接警告。

0.2.6-dev 新增的 `tb_mcd_video` 已通过全部五项检查，实际模拟至 299.527 ms，0 个错误、0 个警告。它检查真实 MCD212 / ICA 经内存突发和 CPU 寄存器写入产生的就绪信号，并核对原生白色光标实际到达 APF 输出；还覆盖背景色屏蔽、后续纯色画面和复位后的两图像平面启动。本次复用视频适配器未变更的 0.2.5-dev 视频结果及此前其他回归结果。新增测试不执行真实 BIOS，因此不以仿真证明特定游戏的音频或实机兼容性。

此前 0.2.5-dev 的适配器视频专项已通过，日志为 `build/sim/tb_video.log` 和 `build/logs/black_screen_test_final.log`；测试手动提供就绪信号，未覆盖 MCD212 实际产生该信号的条件，所以没有发现后续实机持续黑屏反馈。覆盖持续机器复位、未初始化显示的纯色输出、错误原生行宽、切换首个 VS 与元数据、PAL / NTSC / 隔行尺寸、菜单消隐冻结和恢复，以及每次复位时禁止旧 RGB 外露。成功标记为 `ALL VIDEO TESTS PASSED`，模拟运行至 526.510 ms，0 个错误、0 个警告。此次复用了 0.2.4-dev 中未受改动影响的其他测试结果；完整测试脚本改用批处理仿真，避免长测试中的控制台连接中断。

1. 核对两份固件的长度及 README 中的 MD5。安装打包文件，复制未经转换的 CUE 及全部 BIN，选择 `.cue`。分别检查单 BIN、多 BIN 和带空格文件名的盘。
2. 首先确认 BIOS 系统界面能出现、标准按钮能移动指针并点击播放，且没有 DVC。
   切换两张镜像并重复重置，检查核心开始输出后加载期间保持黑屏，再完整显示 CD-i 界面；加载失败也应保持黑屏。FPGA 位流尚未加载时的系统显示不由核心控制。
3. 检查 PAL 默认模式、NTSC 重置启动、Dock 输出和 MCD212 分辨率变化。用隔行画面检查场顺序和垂直抖动。
4. 选择分别使用 CDDA、37.8 kHz XA 和 18.9 kHz XA 的基础软件，检查左右声道、音调、持续播放和寻道后的恢复。
   播放中打开 Pocket 菜单并等待至少 30 秒，确认游戏位置和音轨暂停、输出静音；关闭菜单后继续。重复开关菜单，并检查菜单内核心重置、Dock 控制器和光盘读取中的暂停恢复。
5. 写入游戏存档后进入 Pocket 菜单，再退出核心。检查 `Saves/cdi/common/nvram.sav` 的内容及长度，重新启动同一光盘，确认存档恢复。当前配置在不同光盘间共享这份 NVRAM。
6. 连续运行至少 30 分钟，检查扇区缓存欠载、失音、图像破损和 NVRAM 保存错误。需要 DVC / MPEG 的标题列入首版不支持清单。
7. 将固件版本、光盘校验、显示模式及结果记录成兼容性表后，才将通过的标题标记为实机支持。

开发时可通过 Bridge `0x50000004` 查看状态，`0x50000008` 查看 BIOS / 保存 / 光盘错误，`0x50000010` 查看文件管理程序诊断。发生 BIOS 或 CUE / BIN 启动错误时 CD-i CPU 保持复位。正常光盘文件末尾被预读越过时，光盘错误码为 6，表示越界停止预取。

文件管理诊断高 16 位为阶段：1 获取 CUE 文件名、2 读取 CUE、3 解析布局；低位为错误码：1 CUE 语法、2 不支持格式、3 路径、4 文件 I/O、5 扇区 / 轨道几何、6 范围、7 数据扇区头。`0xFFFF0008` 表示助手 CPU trap。零表示解析完成。
